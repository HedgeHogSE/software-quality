# Подробное руководство по приложению "Моделирование качества ПО на основе ISO"

## Что это за программа?

Это настольное приложение, которое **моделирует изменение качества программного обеспечения во времени**. 

Представьте, что вы разрабатываете программный продукт (например, мобильное приложение или веб-сервис). Качество этого ПО не постоянно - оно меняется в зависимости от:
- Опыта разработчиков
- Условий труда
- Ресурсов
- Внешних факторов (курс валют, репутация и т.д.)

Это приложение позволяет **предсказать**, как будет меняться качество ПО в будущем, если задать определенные начальные условия и внешние факторы.

---

## Для чего это нужно?

### В реальной жизни:

**Сценарий 1: Управление проектом**
- Вы начинаете новый проект
- У вас есть команда с определенным уровнем опыта
- Вы хотите знать: "На каком уровне будет качество через 6 месяцев?"
- Программа дает прогноз на основе математической модели

**Сценарий 2: Планирование улучшений**
- Вы поняли, что качество ПО падает
- Хочется понять: "Какие факторы нужно улучшить, чтобы начать повышение качества?"
- Программа показывает взаимосвязи между факторами

**Сценарий 3: Образовательный**
- Это лабораторная работа по дисциплине "Теория информационных процессов и систем"
- Позволяет понять, как работает система "причина-следствие" в разработке ПО

## Что внутри программы? (Математическая модель)

### Система из 28 уравнений

Представьте, что у вас есть **28 переменных**, каждая из которых характеризует определенный аспект качества ПО:

```
u5   - Сопровождаемость ПО
u24  - Анализируемость
u25  - Изменяемость
u26  - Стабильность
u27  - Тестируемость
u28  - Согласованность
u54  - Документация (не соответствие стандартам)
u55  - Формы документов (не соответствие стандартам)
u56  - Отсутствие лицензии
u107 - Низкий уровень языка
u108 - Отсутствие схемы модулей
u109 - Низкая читабельность кода
u110 - Недостаточно комментариев
u111 - Отсутствие системного подхода
u112 - Слишком большие модули
u113 - Недостатки диагностики
u114 - Недостаточность регистрации
u115 - Высокая трудоемкость изменений
u116 - Низкая параметризация
u117 - Низкая локальность модификации
u118 - Вторичные дефекты
u119 - Недостаточность требований к тестированию
u120 - Отсутствие описания методов испытаний
u121 - Невозможность объективного теста
u122 - Невозможность использования инструментов тестирования
u123 - Не соответствие стандартам сопровождения
u124 - Не соответствие требованиям к исходным текстам
u125 - Отсутствие регистрации изменений
```

**Почему именно 28 переменных?** Это соответствует модели ISO, которая выделяет эти характеристики как ключевые для качества ПО.

### Как эти переменные связаны?

Каждая переменная **не является независимой** - они влияют друг на друга.

Например:
- Если `u54` (документация) ухудшается, это может привести к ухудшению `u5` (сопровождаемость)
- Если `u117` (локальность модификации) ухудшается, это может улучшить `u26` (стабильность), но ухудшить `u25` (изменяемость)

Эти взаимосвязи описаны в **матрице взаимосвязей** (файл `code_artifact.md`), где:
- `1` означает положительное влияние
- `-1` означает отрицательное влияние
- `0` означает отсутствие влияния

### Дифференциальные уравнения

Для каждой переменной написано дифференциальное уравнение вида:

```
du_i/dt = F_i(t, u(t), p)
```

Что это значит?

- `u_i` - текущее значение i-й характеристики
- `t` - время
- `du_i/dt` - скорость изменения характеристики (насколько быстро она меняется)
- `F_i` - функция, которая вычисляет эту скорость на основе:
  - Текущих значений всех переменных `u(t)`
  - Коэффициентов `p`
  - Внешних возмущений

**Простой пример:**
```python
# Упрощенный пример (не из реальной модели)
# Если сопровождаемость (u5) высокая, она может расти
# Если документация плохая (u54), сопровождаемость падает
du5/dt = (положительные факторы) - (отрицательные факторы)
```

### Функции модели (f1-f187)

В уравнениях используются функции, которые преобразуют значения переменных:

1. **Линейная функция:** `f(x) = a*x + b`
   - Пример: `f(x) = 0.25*x + 0.5`
   - Простое пропорциональное влияние

2. **Квадратичная функция:** `f(x) = a*x² + b*x + c`
   - Пример: `f(x) = 0.7*x² - 0.4*x + 0.24`
   - Влияние может ускоряться или замедляться

3. **Кубическая функция:** `f(x) = a*x³ + b*x² + c*x + d`
   - Пример: `f(x) = 0.2*x³ + 0.8*x² + 0.2*x + 0.09`
   - Более сложные зависимости

**Важно:** В оригинальной модели используются 187 таких функций (f1-f187), каждая со своими коэффициентами. Для функций, у которых коэффициенты не указаны, используется простая линейная функция `f(x) = x`.

## Внешние возмущения (Fak1-Fak6)

Это факторы извне, которые влияют на систему. Они **не являются частью качества ПО**, но влияют на то, как меняется качество во времени.

### Fak1 - Опыт разработчиков программного комплекса
- Формула: `Fak1(t) = t² + 1`
- Значение: от 1.0 до 2.0 на интервале [0, 1]
- Что означает: Чем больше опыт, тем лучше условия для улучшения качества

### Fak2 - Опыт работы эксплуатационного персонала
- Формула: `Fak2(t) = cos²(1.5πt - π/6) / 4 + 0.2`
- Значение: колеблется от ~0.2 до ~0.45
- Что означает: Опыт эксплуатантов влияет на обратную связь и выявление проблем

### Fak3 - Трудоёмкость разработки ПО
- Формула: `Fak3(t) = sin(sin(πt - π/6)) / 2.5 + 0.3`
- Значение: колеблется от ~0.1 до ~0.5
- Что означает: Трудоемкость влияет на темпы улучшений

### Fak4 - Курс рубля по отношению к доллару
- Формула: `Fak4(t) = 2t - 1`
- Значение: от -1.0 до 1.0
- Что означает: Экономические факторы влияют на бюджет и ресурсы

### Fak5 - Деловая репутация разработчиков
- Формула: `Fak5(t) = sin²(πt - π/6) / 2.5 + 0.3`
- Значение: колеблется от ~0.1 до ~0.5
- Что означает: Репутация влияет на привлечение талантов и ресурсы

### Fak6 - Деловая репутация эксплуатирующей организации
- Формула: гармоническая функция в диапазоне [0.3, 0.7]
- Что означает: Репутация заказчика влияет на требования и поддержку

## Численное решение системы

### Почему нужно численное решение?

Система из 28 дифференциальных уравнений **не может быть решена аналитически** (в виде формул). Поэтому используется **численное интегрирование** - алгоритм, который вычисляет значения переменных шаг за шагом.

### Как это работает?

1. **Начальное состояние:** Задаются начальные значения всех 28 переменных (например, u5=0.65, u24=0.70, ...)
2. **Вычисление скоростей:** На основе уравнений вычисляется, как быстро меняется каждая переменная
3. **Шаг интегрирования:** С использованием метода Рунге-Кутты вычисляются новые значения переменных
4. **Повторение:** Шаг 2-3 повторяется много раз, пока не достигнем конечного времени

### Метод интегрирования

Используется метод **RK45** (метод Рунге-Кутты 4-5 порядка) из библиотеки `scipy`.

**Что это значит:**
- Это адаптивный метод - он сам выбирает оптимальный шаг интегрирования
- Используется 4 и 5 порядки точности для оценки ошибки
- Для жестких систем (как в нашей модели) может работать медленно

## Что такое 5 реализаций?

В лабораторной работе приведены **5 разных наборов начальных условий**. Это означает, что:
- Одна и та же математическая модель
- Но разные начальные состояния системы

**Почему разные начальные условия?**

Потому что в реальности:
- Разные проекты начинаются с разного уровня качества
- Разные команды имеют разный опыт
- Разные условия эксплуатации

Пример:
- **Реализация 1:** Средний опыт, нормальное состояние
- **Реализация 2:** Низкий старт, много недостатков
- **Реализация 3-5:** Разные комбинации начальных параметров

Каждая реализация даст **другую динамику** - это показывает, как начальные условия влияют на будущее поведение системы.

## Как пользоваться программой

### Шаг 1: Запуск

```bash
python main.py
```

Откроется окно с 4 вкладками.

### Шаг 2: Настройка параметров (вкладка "Параметры")

#### Что такое начальные значения?

Это значения 28 характеристик качества на момент времени t=0.

**Пример значений:**
```
u5  = 0.65   - Сопровождаемость на уровне 65%
u24 = 0.70   - Анализируемость на уровне 70%
u119 = 0.67  - Низкий уровень инструментов тестирования (высокое значение = плохо)
```

**Важно:** Значения в диапазоне [0, 1], где:
- **0** = отсутствие характеристики (очень плохо)
- **1** = полное наличие (отлично)
- **Некоторые переменные (u54, u55, u107, ...) имеют обратный смысл** - 1 = очень плохо, 0 = отлично

#### Как задать значения?

1. Нажмите "Установить по умолчанию" - загрузятся начальные значения Реализации 1
2. Или вручную введите значения для каждой переменной

#### Временной интервал

- **Начало** = 0.0 (обычно не меняется)
- **Конец** = 0.1 (рекомендуется для быстрой работы, можно поставить 1.0, но будет медленно)
- **Шаг** = 0.01 (чем меньше, тем точнее, но дольше)

### Шаг 3: Запуск моделирования

Нажмите кнопку **"Запустить модель"**.

**Что происходит:**
1. Считываются начальные значения
2. Запускается численное решение системы уравнений
3. Вычисляются значения переменных на каждом шаге
4. Результаты сохраняются

**Время выполнения:**
- Интервал [0, 0.1]: ~1-2 секунды
- Интервал [0, 1]: 10+ минут (из-за жесткости системы)

### Шаг 4: Просмотр графиков (вкладка "Графики")

#### Что показывает график?

- **Ось X:** Время (от 0 до конца интервала)
- **Ось Y:** Значение характеристики (от 0 до 1)
- **Каждая линия:** График одной переменной (например, u5, u24, ...)

#### Как читать графики?

**Пример 1: Рост качества**
- Линия идет вверх → характеристика улучшается
- Чем круче подъем, тем быстрее улучшение

**Пример 2: Падение качества**
- Линия идет вниз → характеристика ухудшается
- Чем круче спад, тем быстрее ухудшение

**Пример 3: Стабильное состояние**
- Линия горизонтальная → качество не меняется
- Система достигла равновесия

### Шаг 5: Просмотр возмущений (вкладка "Возмущения")

Тут отображаются графики Fak1-Fak6.

**Что смотреть:**
- Как меняются внешние факторы во времени
- Какие факторы имеют наибольшее влияние
- Взаимосвязи между факторами

### Шаг 6: Просмотр состояния в контрольных точках (вкладка "Состояние системы")

#### Что такое контрольные точки?

Это 5 моментов времени, в которых показаны **точные значения всех 28 переменных**:

| Точка | Время | Описание |
|-------|-------|----------|
| 1 | t = 0.00 | Начальное состояние |
| 2 | t = 0.025 (при t_end=0.1) | 1 четверть |
| 3 | t = 0.05 (при t_end=0.1) | Половина пути |
| 4 | t = 0.075 (при t_end=0.1) | 3 четверти |
| 5 | t = 0.10 (при t_end=0.1) | Конечное состояние |

**Если t_end = 1.0, точки будут:** 0.00, 0.25, 0.50, 0.75, 1.00

#### Как читать таблицу?

Каждая строка - состояние всей системы в определенный момент.

**Пример строки:**
```
u5=0.72, u24=0.68, u25=0.61, ..., u125=0.45
```

Это значит, что в этот момент времени:
- Сопровождаемость = 72%
- Анализируемость = 68%
- Изменяемость = 61%
- ...

## Как интерпретировать результаты

### Вопрос 1: "Почему качество падает?"

**Возможные причины:**
1. Высокие начальные значения "негативных" переменных (u54, u55, u107, ...)
2. Низкие значения "позитивных" переменных (u5, u24, u25, ...)
3. Внешние факторы (Fak1-Fak6) благоприятны

**Что делать:**
- Построить графики для всех переменных
- Найти, какие переменные снижаются быстрее
- Попробовать изменить начальные условия

### Вопрос 2: "Как улучшить качество?"

**Возможные способы:**
1. Увеличить начальное значение "позитивных" переменных
2. Уменьшить начальное значение "негативных" переменных
3. Оптимизировать внешние факторы (если это в ваших силах)

**Пример:** Если `u119` (недостаточность требований к тестированию) = 0.9, попробуйте уменьшить его до 0.6 и запустить модель снова.

### Вопрос 3: "Почему разные реализации дают разные результаты?"

Потому что **начальные условия критически важны** в нелинейных системах.

**Простой пример из жизни:**
- Запуск с высоким качеством (u5=0.8) → качество растет или стабильно
- Запуск с низким качеством (u5=0.3) → качество может падать или быстро улучшаться

Это называется **чувствительность к начальным условиям** - малое изменение в начале может привести к большому различию в конце.

## Ограничения и проблемы

### 1. Жесткость системы

**Что это:** Система из 28 уравнений имеет разные временные масштабы - некоторые переменные меняются очень быстро, некоторые очень медленно.

**Что это значит:**
- Для точного решения нужны очень маленькие шаги
- Работа на интервале [0, 1] занимает 10+ минут
- Возможны проблемы с точностью

**Решение:**
- Использовать интервал [0, 0.1] для быстрой работы
- Или использовать специальные методы для жестких систем (Radau, BDF)

### 2. Неполнота данных

В оригинальном документе не все коэффициенты функций были указаны. Для некоторых используется упрощенная функция `f(x) = x`.

**Что это значит:**
- Модель может не точно воспроизводить оригинальную лабораторную работу
- Но принципы работы верны

### 3. Упрощенная модель

Модель - это **упрощенное представление реальности**. Она учитывает 28 факторов, но в реальности их гораздо больше.

**Что это значит:**
- Модель полезна для понимания основных тенденций
- Но не заменяет детальный анализ конкретного проекта

## Часто задаваемые вопросы

### Q: Почему приложение зависло?

A: Скорее всего, вы указали интервал [0, 1] - это жесткая система и работает медленно. Попробуйте интервал [0, 0.1].

### Q: Какие значения считать "хорошими"?

A: Для большинства переменных:
- Значения ближе к 1 = лучше (кроме "негативных" переменных)
- Для переменных u54, u55, u107, ...: значения ближе к 0 = лучше

### Q: Можно ли экспортировать результаты?

A: Сейчас это заглушка - результаты только отображаются в интерфейсе. В будущем можно добавить экспорт в CSV или PNG.

### Q: Почему нет описания каждой переменной?

A: В оригинальном документе не все переменные имели четкое описание. Некоторые имеют только обозначения u5, u24 и т.д.
